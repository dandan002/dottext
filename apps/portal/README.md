# Portal

Build the private portal with Next.js, TypeScript, and the [Astryx](https://www.npmjs.com/package/@astryxdesign/core) design system, on a local `dottext` theme that extends `neutral` with 16px body text, 1.6 line height, stronger secondary text in dark mode, and softened greys in place of black: charcoal text and primary buttons in light mode (`#2b2b2b`, `#474747`), and a `#262626` ground with `#303030` panels in dark mode. This replaces the earlier Tailwind and shadcn/ui working default.

## Current state

A design shell: no real auth, data access, or research routes.

| Route | What it shows |
| --- | --- |
| `/login` | Sign-in form outside the app frame |
| `/briefings` | Reading view with country/period controls, analyst tabs, **Copy** (rich text with a plain-text fallback) and **Download** (.md, .txt, .html) |
| `/research` | **Agent** tab (question composer, transcript, explicit evidence gaps, separate live-search action) and **Headlines** tab (news grouped by country, filterable by period, topic and keyword; selecting a headline hands it to the agent) |
| `/coverage` | Source health and spend; the roster mirrors the inactive candidates in `config/sources` |
| `/account` | Profile, timezone, briefing defaults, workspace, sign out; also reachable from the account menu at the bottom of the rail |

**Sign-in is a preview stub** (`src/lib/session.tsx`): any email starts a browser-local session and nothing is verified or protected. Replace it with the chosen provider and server-side workspace checks before any real data is served; see [open decisions](../../docs/decisions.md). Briefing prose and headlines are labeled on screen as sample content, not collected evidence.

```bash
npm install            # from the repository root
npm run dev -w @dottext/portal
npm run build -w @dottext/portal
npx astryx doctor --built .   # from this directory, before delivering UI changes
```

## Design conventions

`AGENTS.md` (generated by `npx astryx init`) holds the rules agents and people should follow here. In short: start pages from an Astryx template (`npx astryx build "<idea>"`), compose with components rather than raw elements, use tokens instead of hex or pixel values, render dense data as Table or List rows, and change colors or fonts through the theme. The theme's source of truth is `themes/dottext/dottext.settings.json`, changed only with `npx astryx experimental theme editor set dottext …`; it rebuilds `src/themes/dottext/`. `src/astryx-themes.ts` is generated by `npx astryx theme add|use`. Astryx ships prebuilt CSS, so no StyleX compiler is configured. Base CSS is imported in `src/app/layout.tsx`; links route through Next.js via `LinkProvider` in `src/app/providers.tsx`.

## Build sequence

1. Choose auth and resolve authenticated users to workspace memberships on the server.
2. Add archive/results/detail views, country/date/source/topic/document-type filters, keyword search, and a coverage panel.
3. Add cited question answers with matching documents beside them, explicit evidence gaps, and a separate “Search live sources” action. Show durable live-job status and newly retrieved result times.
4. Add briefing controls for selected countries and 24-hour/seven-day periods, saved history, and separate analyst views.
5. Add private follows, feedback, source exclusions, schedules, usage/paused states, and correction views.

## Research routes

Host thin authenticated research route handlers here initially: `POST /v1/briefings`, `POST /v1/research`, `GET /v1/briefings/{id}`, `GET /v1/usage`, plus workspace-scoped schedules, follows, feedback, and correction views. Define exact remaining route shapes in contracts before implementation. Dispatch long work durably; return a job reference instead of holding a request for the full workflow. Shared research logic lives in `packages/research`; evidence is accessed through the content API.

## Display and validation

Show generation time, exact evidence cutoff, countries, reading time, coverage status, and source links. Keep saved prose immutable. Show corrections and linked updates. Differentiate quiet coverage, failure, overdue collection, insufficient evidence, and budget pause. Schedule timezone is configurable and initially America/New_York.

Validate private server-side access with two workspaces; include history, feedback, schedules, caches, artifacts, and job results. Validate the full requested briefing/research flows against [product](../../docs/product.md) and [pilot criteria](../../docs/pilot.md). Do not surface retrieval scores as confidence.
