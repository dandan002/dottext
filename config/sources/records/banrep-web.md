# banrep-web — Banco de la República website

| Field | Value |
| --- | --- |
| Source ID / publisher | `banrep-web` / Banco de la República (Colombia's central bank) |
| Country / language | Colombia / Spanish (complete) and English (translated subset) |
| Status | **Validating** — parsers validated on live pages; collection gated by bot protection (below) |
| Discovery endpoint and method | Paginated Drupal 11 listings, newest first: `https://www.banrep.gov.co/es/noticias?page=N` (8 rows/page, ≈297 pages) and `/en/press-releases?page=N` (20 rows/page, ≈43 pages). Both include Board decisions, minutes, Monetary Policy Report notices, FX/TES operations, and other releases. Board-only listings (`/es/comunicados-junta`, `/en/press-releases-board`) are subsets and not needed. Paging stops at the first row older than the window. The front-page RSS (`/es/rss.xml`) is not used: 10 items, sticky 2016–2021 nodes on top, `pubDate` is node creation time. |
| Article and attachment extraction | `main [data-history-node-id]` node: title `#block-banrep-pagetitle h1`; lead `.field--name-field-general-txt` (stored as standfirst); body `.field-name-body` paragraphs, table rows joined with ` \| `; attachments = links to files, `/sites/default/files/`, or repository bitstreams/handles; related items `.field--name-field-publication-reference`. |
| Publication/modification/event time parsing | Listing and article dates are Drupal date-only fields serialized as `YYYY-MM-DDT12:00:00Z` — only the date part is used. The separate "Hora"/"Time" value is Bogotá wall-clock time (America/Bogota, UTC−5, no DST); with it, precision is minute and basis `publisher_default`; without it (English articles, Board listing), precision is day. No modification time is exposed (null). |
| First-seen/collection handling | `firstSeenAt` = first discovery by our pipeline; `collectedAt` = fetch time of each revision. Never substituted for publication time. |
| Actual history range and gaps | Not measured. Listing depth suggests multi-year history; a one-month backfill has not completed because of bot protection. |
| Access/retention terms and supporting references | [Legal notice](https://www.banrep.gov.co/en/legal-notice) (reviewed 2026-11-17): content is copyrighted; reproduction only where authorized or under legal exceptions, citing the source; commercial/promotional use needs prior authorization; no use that overloads the Bank's systems. Owner confirmation pending. |
| Permitted full text / excerpt / metadata / snapshots | Configured `full_text` for private internal research with citation; no snapshots. **Owner to confirm** against the legal notice before activation. Test fixtures are synthetic for this reason. |
| Duplicate and correction behavior | Spanish and English versions share a Drupal node ID → `translationGroup: banrep-web:node:<id>`, plus `hreflang` alternates. English is a translated subset; some items are English-only. Corrections are detected by content hash on refetch (items listed within 7 days are refetched) and stored as linked revisions. |
| Failure, retry, and rate behavior | **Radware Bot Manager (ShieldSquare)** fronts `*.banrep.gov.co`. On 2026-11-17, with an honest User-Agent and ≥4 s spacing, the first ~5 requests passed, then challenges rose to 100% from the same IP for ~20 minutes; the default `curl` UA was challenged immediately. Real pages embed the Radware script, so detection uses challenge-page titles/redirects, not script presence. Client: 10 s spacing, 10 requests/run, breaker after 2 consecutive challenges, no retry of challenges; failed items stay pending for later runs. |
| Validation fixtures and run evidence | `packages/connectors/test/fixtures/banrep/*` (synthetic text, real structure). Parsers run against real pages captured 2026-11-17 (not committed): listing rows/dates/times, article title/lead/body, node 66475 twin link, 13:00 Bogotá → 18:00Z all correct. |
