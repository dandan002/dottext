# Delivery sequence

Implement vertical slices in this order. Directory existence does not indicate readiness. Every stage must preserve workspace permissions, evidence provenance, and budget controls for the work it enables.

| Stage | Build | Exit evidence |
| --- | --- | --- |
| 1. Content baseline | Validate connectors; backfill sample; document/passage contracts; processing, persistence, minimum content API; usage measurement | Permitted official and journalism samples for both countries, revision/timestamp fixtures, actual coverage and costs; database benchmark |
| 2. Core portal | Choose auth; login/workspace; archive, filters, keyword search, source health | Private browsing works; cross-workspace checks pass; failure differs from quiet coverage |
| 3. Research | Hybrid retrieval; cited answers; manual live retrieval; model adapter and tracing | English questions retrieve Spanish evidence; unsupported answers show gaps; explicit live action returns durable job status |
| 4. Analyst briefing | Country profiles/checks; local color, macro, political workflows; editor; cached sections and saved assessments | Selectable 24-hour and weekly outputs, citations/cutoffs, Codelco coverage fixture, editorial review |
| 5. Automation | User schedules; retries; corrections; budget alert/stop UX | DST and execution-deduplication checks, concurrent reservation checks, correction links and review propagation |
| 6. Pilot review | Two-week user evaluation and measured cost | Acceptance results, coverage gaps, usefulness judgments, expansion decision |

Do not defer all budget/security work to stage 5: minimum enforcement must precede cost-incurring or private-data paths. Stage 5 completes the automated and user-visible behavior.

Start by selecting the local toolchain, defining validated contracts, building one permitted-source-to-passage slice, and measuring its cost. Extend to both countries and official/journalistic sources before making coverage claims. Keep unresolved choices in [decisions](decisions.md). Use [pilot criteria](pilot.md) to record verification evidence rather than checking boxes from implementation alone.
